# ACGMaker

終於搞定了，現在應該真的是無外部程式庫與無bug狀態(應該吧？)／(。>_<)~

---

### 簡介

ACGMaker，顧名思義，是創作動漫的工具，在2021年時，我想要打造一個「高畫質版本的Scratch」，就建立了它，可以用它來製作簡單的網頁遊戲。

取這個名字，是認為之後會加入其他「ACGM」的創作功能，但在2022年之後，也沒有再繼續更新了。

不過在最近兩三年，我常用的影像軟體，甚至是小畫家 (它曾經是最可靠的工具啊)，都開始出現效能問題，記憶體消耗過多，啟動速度也越來越慢，所以從去年開始，我才真正加入了影像處理工具。

---

### 程式特點

#### 不使用外部程式庫

我不擅長使用別人寫好的東西，我常常抗拒使用OpenCV之類的工具，想要自己刻，但這樣的(缺點？)反而讓我在過程中更容易理解背後的數學原理，執行檔的大小也更小了，我也推薦你這麼做。

所以我習慣使用原生的程式語言製作軟體，連jQuery、bootstrap都沒有，程式大小非常小，且直接將程式碼Clone下來就可以使用，這或許是非常少見的。

#### 直接操作像素

大多數的影像處理演算法是在5~10年前完成的(使用VB, C++)，我使用之前寫的東西在網頁上重新建立全新的程式，無需依賴Canvas提供的繪製方法。

### 本專案想要解決的問題

#### 效能問題： 

我對軟體業有個很大的期望就是，我只要點兩下，就可以秒開任何軟體，也不會什麼都沒做就消耗我300MB的記憶體，即便那是個龐大的遊戲引擎。

不過，我過去使用一些「比較迷你」的遊戲引擎，但啟動速度顯然遠遠慢過這個期望。

而且，我作為一位遊戲玩家，也希望不會連載個小遊戲，都要佔用數百MB的硬碟空間。

#### 舊版系統支援： 

我喜歡使用Windows 7，但許多軟體現在已經不再支援Windows 7了，這很可惜，我短期內不會想放棄它，除非微軟終於開發出了比Windows 7更穩定的工具。

#### 中文支援度不足： 

我在學習操作某些遊戲製作軟體時，看到視窗中有許多英文、或是「視頻」之類的非本土用語，閱讀上都有些吃力，我認為中文化對許多人來說，可以減少適應一項軟體的時間。

#### 隱私問題： 

(此地無銀三百兩的一句話：我們在乎您的隱私) 當我點開某些繪圖軟體時，它們可能會以檢查更新/檢查授權，或是「增進使用者體驗」的名義，對外寄送資料，我並不喜歡這樣，天知道它到底寄送了什麼資料出去，甚至也不喜歡我點開軟體時，地球的某個地方會有人知道我正在畫圖。

#### 找不到按鈕的問題： 

我視力不好，畫圖時常常找不到我要的那個按鈕在哪裡，所以你會看到，那些按鈕都有顏色。

#### 畫錯圖層問題

我認為，替筆刷和圖層用tag建立關聯，可以在切換圖層時只顯示關聯的的筆刷，構想時感覺是可行的，但這個想法在實作上會牽扯到很多問題，筆刷變來變去會使人疑惑，目前打算改為用狀態列提醒。

#### 圖稿修改問題

初學者畫圖時，常常遇到一些不知道怎麼修改的問題，像是髮流沒有從一個中心點延伸、配色比例等，但對於將圖片上傳到網路上(尤其是有作權議題的網站上)詢問，他們常常會有些疑慮，我認為可以做一些實驗，試著在軟體內先做簡易的偵測。

#### 缺乏開放的跨視窗標準： 

目前市面上主要的繪圖工具，有個對我來說很大的困擾就是，在跨軟體傳輸上，沒有支援開放的標準。

想像一下，在自己需要用另一個軟體後製影像的一部分時，我可以直接將圖層拖曳到另一個軟體上編輯，再拖曳回來，無需另存檔案，寶貴的專注力得以繼續存續。

OpenRaster或許是一個可行的測試標準，不過目前還在研究可行性。

---

### 還在克服的困難

#### 桌面視窗版本

原先有許多功能是使用C/C++語言編寫的，但我實在是，嚴重低估了使用Win32 API製作GUI，程式碼內的一切都容易複雜化的難題 (即便許多功能都已寫成函數)，所以目前只有網頁版，桌面視窗的版本暫時還在處理。

#### 網頁版本

許多功能搬到網頁版後，效能不足的問題浮現了出來，導致無法讓所有的功能都遷移至網頁上，這部分還在克服。
